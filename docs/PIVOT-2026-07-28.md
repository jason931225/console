## What changed

### 1. The entire frontend was deleted (intentional, authorized)

Removed — 1,820 tracked files:

| Removed | Note |
|---|---|
| `web/` | React + Vite console and legacy app |
| `clients/ts`, `clients/kotlin`, `clients/swift` | generated API clients |
| `e2e/` | Playwright specs |
| `android/`, `ios/`, `fastlane/`, `gradlew`, `Gemfile*` | native apps + release tooling |
| `playwright.config.ts`, `openapitools.json`, `tsconfig.json` | frontend build config |
| `.github/workflows/ios-ui-tests.yml` | mobile CI |

Consequences: the three OpenAPI client-drift gates no longer exist; the Kotlin monolithic-`DefaultApi.kt`
OOM hazard is gone; `check-i18n` cross-platform string parity is gone; there is currently **no**
frontend of any kind.

### 2. Repo renamed: `maintenance` → `console`

- Local path: `~/Developer/console` (was `~/Developer/maintenance`)
- Remote: `github.com/jason931225/console`
- **`mnt`, `mnt-*`, `maintenance`, and the DB role `mnt_rt` are all deprecated.** Because the rebuild is
  greenfield-by-design, the previously infra-bound `mnt_rt` role rename no longer requires a
  dual-alias live migration — new names are chosen outright.

### 3. Frontend stack decided: Leptos, not React

| Decision | Value |
|---|---|
| Framework | **Leptos 0.9 (beta)** — SSR with islands / selective hydration |
| Rejected | Next.js 16.2.12 / RSC, React, React Native |
| Why | Every component in this design is hand-rolled (inline styles, hand-inlined stroke SVG; the charter bans component-library aesthetics), so React's ecosystem advantage would go uncashed — while TS would restore the codegen tax just deleted. One language lets changes cross the server/client seam atomically. |
| Server integration | `leptos_axum` — backend already uses axum 0.8.9 |
| Call boundary | Server functions **and** REST as sibling adapters over the same application-layer use-cases |
| Isolation | Leptos lives behind a contracts crate and stays **out of default workspace members** until shell work begins, so 0.9-beta churn cannot break backend lanes |

The frontend returns **last**, as the acceptance test, rebuilt from `console.dc.html` in Claude Design
project `198fcee4-d6bb-4cd0-b567-72c4b67c62eb` ("기본") — a 23.7 KB **shell only**: sidebar (empty nav),
main column (empty section), comms rail with four empty collapsible sections (메신저/메일/알림/공지),
responsive drawers under 900px, 2-way light/dark theme.

### 5. Scope narrowed, hard

**Ontology · Foundry · Policy** as one governed object engine, then **Organization + Employee**, then
**HR + Payroll**. Stated boundary: *"that's it — those are the building blocks of a company."*

Explicitly **out**: ERP modules, field ops, dispatch, comms modules, compliance modules, ingest,
evidence/WORM, office editor. Benchmarks: **AWS Cedar** (policy), **Palantir Foundry** (ontology,
actions, lineage). No AI/LLM judgment anywhere — deterministic or manual.

### 6. Build system: cargo, not buck2

buck2's justification was polyglot builds (Rust + Kotlin + Swift + TS); every non-Rust surface is now
deleted. Pure Rust ⇒ cargo is native. Chosen: **sccache** (shared cache across worktrees) +
per-lane `CARGO_TARGET_DIR` + `cargo-nextest` + profile tuning. The repo has **no** `.cargo/config.toml`
(only `backend/.cargo/audit.toml`); `backend/Cargo.toml:359` already carries `[profile.dev]` and
`[profile.test]` with `debug = "line-tables-only"` — that is the whole of the tuning done so far.

### 7. The engine is NOT greenfield — it largely exists

Verified 2026-07-28 by direct inspection:

| Asset | Size | Location |
|---|---|---|
| Ontology engine (§18 model: `SchemaLifecycleState`, `BackingKind`, `LinkCardinality`, `ActionDispatch`, `InstanceLifecycleState`, `FieldKind` — all in `ontology/domain/src/lib.rs`) | 17,825 LOC | `backend/crates/ontology/` |
| Cedar partial-eval → SQL `WHERE` residual | 7,861 LOC | `backend/crates/platform/authz/` (`cedar_pbac.rs`, `cedar_pbac/residual.rs`) |
| Audit chain | 2,327 LOC | `backend/crates/platform/audit-chain/` |
| Cedar | pinned `4.11.2` | `platform/authz/Cargo.toml:17` |

"Reimagine" therefore targets **substrate + composition**, not a rewrite of these. Reuse posture:
the existing backend is a **quarry** — harvest patterns, owe nothing to its shape.
